# Docking Agent · 실제 실행과 결과 읽기

도식과 실제 1IEP 실행 결과로 읽는 9단계 강의입니다. 개인 학습 사례이며 공식 평가 결과가 아닙니다.

## 1. 도킹 Agent, 무엇을 만들었을까?

도킹은 단백질과 화합물이 결합할 때 가능한  3차원 자세 를 찾는 일입니다.

이 실습에서는 Codex가 요청을 해석하고 도구 호출을 판단합니다. Python 실행기는 도킹 프로그램을 실행하고 결과와 로그를 돌려줍니다.

현재 만든 것은 이 연결 경로입니다. 별도 LLM API를 넣은 독립 앱이나 자동 기권 정책까지 구현한 상태는 아닙니다.

판단하는 부분과 계산하는 부분을 나눠 봅니다.

## 2. LLM·하네스·엔진은 각각 무엇을 할까?

Codex가 요청을 해석하고 어떤 도구를 실행할지 판단합니다. 분자의 좌표를 직접 계산하는 엔진과 역할이 다릅니다.

하네스는  입력 검사, 실행 조건, 제한 시간, 로그와 결과 보존 을 담당합니다. 엔진은 실제 도킹 계산을 수행합니다.

현재 Vina와 Vina-GPU는 공통 실행기에 연결했고, DiffDock-L은 별도 CLI로 검증했습니다. 이번 경로는 ToolUniverse에 직접 의존하지 않습니다.

LLM의 판단과 엔진의 성능을 따로 관찰합니다.

## 3. 서로 다른 파일에 같은 분자가 들어 있을까?

Vina는 준비된  PDBQT , DiffDock-L은 단백질  PDB 와 리간드  SDF 를 받습니다.

이번에는 단백질 중원자 2,229개의 좌표를 대조했고, 리간드 중원자 37개도 같은 원자로 대응시켰습니다.

이렇게 해야 후보 자세가 달라졌을 때  입력부터 다른 실험이었는지 와  예측 결과가 다른 것인지 를 구분할 수 있습니다.

같은 좌표계와 같은 참조에서 비교합니다.

## 4. 같은 입력인데 왜 비교 조건은 다를까?

Vina와 Vina-GPU에는 알려진 포켓을 중심으로 한 20 Å 정육면체 박스를 주었습니다. 이 안에서 화합물의 배치를 탐색합니다.

기본 DiffDock-L에는 그 박스를 주지 않았습니다.  단백질 전체에서 결합 위치와 자세를 예측 하는 조건입니다.

같은 구조를 써도 주어진 정보와 탐색 문제가 다릅니다. 후보 수도 Vina는 최대 5개 요청, DiffDock-L은 기본 10개 생성으로 달랐습니다.

이 표로 일반적인 도구 순위를 정하지 않습니다.

## 5. 세 도구를 실행하면 어떤 값이 나올까?

이번 조건에서 Vina의 최고 순위가 준비된 참조와 더 가까웠습니다.  탐색 위치·후보 수·시간에 포함된 작업은 서로 다릅니다.

Vina의 도킹 에너지와 DiffDock-L의 confidence는 다른 점수입니다. 같은 숫자 척도로 친화도를 비교하지 않습니다.

수치 옆에 실행 조건을 함께 읽습니다.

## 6. 최고 순위와 정답에 가장 가까운 후보는 같을까?

RMSD 는 대응하는 원자들의 좌표 차이를 거리 하나로 요약한 값입니다. 이번에는 리간드를 따로 정렬하지 않았습니다.

DiffDock-L의  1위는 15.616 Å , 10개 중 참조와 가장 가까운  5위는 4.198 Å 였습니다.

5위가 가장 가깝다는 것은  참조를 아는 상태에서 사후 계산 한 결과입니다. 모델이 정답 없이 그 후보를 1위로 선택했다는 뜻은 아닙니다.

후보 생성과 후보 순위의 품질을 구분합니다.

## 7. 실행이 끝났는데도 실패 후보가 남을까?

추론은 끝났지만 NaN 복구 경고가 기록됐습니다. 원본 DiffDock 코드는 비정상 점수를 작은 값으로 바꾸어 계산을 이어갑니다.

10위 후보는 좌표가 발산해 결합 길이가  0–9.90 Å 로 나타났습니다. 파일이 읽히고 숫자가 유한해도 이 화합물의 정상 자세로 볼 수 없습니다.

기본 결합 길이 검사는  9개 통과·1개 실패 였습니다. 통과한 9개도 정답 자세라는 뜻은 아닙니다. PoseBusters·충돌·친화도 검증은 하지 않았습니다.

실행 완료와 예측 품질을 분리합니다.

## 8. 첫 실행은 왜 오래 걸렸고, 어디까지 재현했을까?

첫 실행에는 회전·비틀림 분포 테이블 생성이 필요했습니다. 이후 실행은 그 파일을 재사용했지만 모델 로딩·임베딩·모듈 초기화 비용은 남아 있습니다.

같은 시드로 두 번 실행했고 최고 순위 RMSD는 비슷했습니다. 후보 전체가 비트 단위로 같지는 않았고, 발산 후보도 두 실행에 남았습니다.

1IEP는 DiffDock 저장소의 학습 split 목록에 포함됩니다.  이번은 Windows 실행과 결과 검사 사례이며, 처음 보는 화합물·타겟의 성능 평가가 아닙니다.

재실행 확인과 미학습 일반화를 구분합니다.

## 9. 이 실습에서 가져갈 핵심은 무엇일까?

Codex는 호출을 판단하고, 실행기는 조건과 기록을 관리하며, 엔진은 후보를 계산합니다.

판단에 필요한 것은 점수 하나가 아니라  입력·탐색 조건·좌표·시간·경고 입니다.

이번 구현은 그 기록을 남기고 비교하는 단계입니다. 범용 자동 재시도·기권 정책과 실험 친화도 정확도는 아직 검증하지 않았습니다.

‘돌아갔다’ 다음에 ‘무엇을 믿을 수 있나’를 묻습니다.

개인 개발·학습 사례입니다. 공식 프로젝트의 평가 결과나 평가 규약을 뜻하지 않습니다.
