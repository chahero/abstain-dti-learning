전체 표시 원고

S01 · 쉬운 문제와 낯선 문제를 어떻게 나눌까?

정확도가 같은 모델도 낯선 분자나 타겟에서는 다르게 실패할 수 있습니다. 결과를 하나의 평균으로 합치면 어디에서 자신감을 잃어야 하는지 알기 어렵습니다. 오늘은 문제마다 낯섦과 근거의 좌표를 붙입니다.

난이도 좌표는 정답을 보고 어렵다고 붙인 꼬리표와 다릅니다. 학습 데이터와의 화학적 거리, 타겟의 친숙함, 구조 근거처럼 정의할 수 있는 정보를 계산합니다. 이후 결과와 어떤 관계가 있는지 검토합니다.

실제 cold-drug 데이터에서 질문 12개와 좌표 표를 만들겠습니다. 계산한 값과 아직 조회하지 않은 값을 명확히 나누고, 출처와 검증 기록을 남기는 큐레이션 과정을 공부합니다.

S02 · 좋은 질문에는 대상과 정답의 정의가 있다

질문에는 어떤 분자와 어떤 단백질을 묻는지 명확한 식별자가 필요합니다. 이름만 적으면 염, 입체 이성질체와 변이가 섞일 수 있습니다. 구조 문자열과 정확한 서열의 식별자를 함께 보관합니다.

이번 질문은 공급된 Kd가 100 nM 이하인지입니다. 경계값 레코드는 제외 상태로 남깁니다. 측정 종류나 실험 조건이 다른 데이터와 합쳐 일반적인 결합 여부의 정답으로 승인하지 않습니다.

정답의 출처와 판단 규칙, 검토 상태를 같이 남겨야 다른 사람이 다시 확인할 수 있습니다. 쿼리 문장이 자연스러운 것과 정답이 검증된 것은 다릅니다. 질문과 정답의 근거를 분리해서 읽습니다.

S03 · 질문 표와 좌표 표를 같은 키로 연결한다

질문은 JSONL에 한 줄씩 저장하고, 난이도 좌표는 TSV 표에 저장할 수 있습니다. 두 파일은 같은 질문 식별자를 사용합니다. 순서가 달라져도 같은 문제의 데이터가 연결되도록 합니다.

모델 실행 로그도 같은 질문 식별자를 기록합니다. 그러면 원래 질문, 정답, 좌표, 도구 반환과 최종 판단을 한 문제 단위로 모아 볼 수 있습니다. 행 순서에만 기대면 중간에 누락된 결과가 다른 질문에 붙을 수 있습니다.

식별자가 중복되거나 결과가 빠진 경우를 검사합니다. 실행에 성공한 문제만 남기는 필터를 조용히 쓰지 말고, 누락과 제외 사유를 기록합니다. 쿼리의 개수와 평가 분모를 일치시키는 기본 준비입니다.

S04 · 좌표의 기준은 평가 조건의 train이다

화학적 거리와 서열 친숙함은 어느 학습 데이터와 비교했는지에 따라 달라집니다. random의 train과 cold-drug의 train을 섞어 쓰면 같은 좌표 이름이어도 다른 의미가 됩니다. 참조 분할을 먼저 고정합니다.

평가 문제끼리 가까운지로 학습 친숙함을 대신하지 않습니다. 평가에만 있는 분자를 비교 대상에 넣으면 실제 모델이 본 범위보다 쉬운 문제처럼 보일 수 있습니다. 참조 목록과 데이터 해시를 저장합니다.

이번 표는 cold-drug의 train을 참조합니다. 분할은 앞선 실습의 동결된 배정을 재사용했습니다. 공식 프로젝트가 선택한 좌표 스키마를 확정한 것이 아니라, 개인 학습용 정의와 예제입니다.

S05 · Morgan fingerprint로 화학적 거리를 만든다

분자를 Morgan fingerprint의 비트 벡터로 표현하고 Tanimoto 유사도를 계산합니다. 각 질문 분자와 train 분자들의 유사도 중 가장 큰 값을 찾습니다. 가장 가까운 학습 분자를 기준으로 친숙함을 읽습니다.

화학적 거리의 기준값은 1입니다. 여기에서 최대 유사도를 빼는 값으로 정의했습니다. 값이 클수록 이 표현에서 학습 분자와 더 멀다는 뜻입니다. 표현의 반지름과 비트 수가 바뀌면 값도 달라질 수 있습니다.

이번 설정은 반지름 2와 2048비트입니다. 같은 문자열 기준, RDKit 버전과 설정을 같이 보관합니다. 이 값이 분자의 모든 물리적 차이나 약효 차이를 뜻한다고 확대하지 않습니다.

S06 · 가장 가까운 분자를 원본까지 확인한다

최대 유사도 숫자만 남기지 말고, 가장 가까운 train 분자의 식별자도 남길 수 있습니다. 두 구조를 나란히 보면 같은 고리와 다른 치환기, 입체 정보와 염이 어떻게 반영됐는지 해석하기 쉽습니다.

해시 비트 표현은 서로 다른 부분 구조가 같은 비트에 들어가는 충돌을 가질 수 있습니다. 높은 유사도가 정확히 같은 분자라는 증거는 아닙니다. 분자 동일성은 별도의 표현과 정책으로 확인합니다.

특히 염 제거, 전하와 토토머 표준화의 선택은 결과에 영향을 줍니다. 이번 데이터는 canonical isomeric SMILES를 썼으며 그런 추가 표준화를 전부 수행했다고 표시하지 않습니다. 처리 정책을 좌표와 함께 남깁니다.

S07 · 새로운 골격도 별도 좌표가 된다

Murcko scaffold를 계산하면 고리와 링커의 뼈대를 비교할 수 있습니다. 질문의 scaffold가 train 목록에 있는지 확인해, 새로운 골격 여부를 이진 좌표로 만들었습니다. 화학적 거리와 비슷해 보여도 같은 정의는 아닙니다.

이번 scaffold 계산은 입체성을 포함하지 않는 설정입니다. 전체 분자 표현의 입체 정보와 scaffold의 정책이 서로 다르므로, 같은 골격이라는 말의 범위를 명시합니다. 고리가 없는 분자의 빈 골격도 해석이 필요합니다.

가까운 fingerprint를 가진 분자가 새로운 골격일 수도 있고, 같은 골격이라도 치환기가 달라질 수 있습니다. 두 좌표를 동시에 보면서 무엇이 낯선지 설명합니다. 하나의 숫자로 모두 합쳐 버리지 않습니다.

S08 · 서열 좌표는 무엇과 비교했는가?

서열 유사도는 타겟이 학습 단백질과 얼마나 가까운지 설명할 수 있습니다. 일반적인 경우에는 정렬 방식과 같은 잔기의 분모, 비교 영역을 정의해야 합니다. 단순한 이름 일치로 서열 유사도를 계산하지 않습니다.

이번 cold-drug 예제의 질문 타겟은 정확한 서열이 train에 이미 있습니다. 따라서 train과의 최대 서열 동일률은 100%입니다. 서열 해시가 실제로 같은지 확인했으며 새로운 타겟을 정렬하는 계산을 했다고 주장하지 않습니다.

cold-target에서는 다른 서열을 비교해야 하므로 별도의 정렬 정책이 필요합니다. 정확히 같은 서열이 없다는 것과 낮은 유사도라는 말도 다릅니다. 이전 split 영상에서 배운 개체 배정과 친숙함 좌표를 구분합니다.

S09 · pocket pLDDT는 구조 근거의 좌표다

AlphaFold 구조에서 선택한 pocket 잔기의 pLDDT 평균을 좌표로 둘 수 있습니다. 구조 전체 평균보다 질문의 부위에 가까운 정보를 요약합니다. 어떤 pocket과 어떤 잔기 집합인지 출처가 필요합니다.

높은 pLDDT는 해당 예측 구조의 국소 신뢰 정보입니다. 약물이 결합할 확률이나 친화도의 확신으로 바로 바꿀 수 없습니다. 구조의 출처와 사용한 모델, pocket 검출 방식과 잔기 번호를 함께 남깁니다.

이번 열은 아직 계산하지 않았으므로 NA로 표시했습니다. 앞선 ON04의 한 타겟 구조 값을 다른 타겟이나 변이에 복사하지 않습니다. 정확한 서열과 구조 매핑을 확인한 뒤 실제 값을 채워야 합니다.

S10 · 실험 구조를 안 찾았다는 말은 없다와 다르다

실험 구조 존재 여부를 좌표로 쓰려면 검색 범위와 타겟 매핑을 정해야 합니다. 단백질 이름으로 PDB 결과가 하나 나왔다고 질문의 정확한 변이와 부위를 확인한 것은 아닙니다. 서열과 구성체를 대조합니다.

조회하지 않음, 조회 실패, 검색 범위에서 찾지 못함과 정확히 대응하는 구조를 찾음은 다른 상태입니다. 모두 영으로 합치면 데이터 준비의 차이가 타겟의 생물학적 난이도처럼 보일 수 있습니다.

이번 표는 외부 구조 검색을 수행하지 않았으므로 미조회로 표시했습니다. 실험 구조가 없다고 단정하지 않습니다. 나중에 조회 시각과 질의, 후보 엔트리와 검토 결과를 기록하며 상태를 갱신합니다.

S11 · 학습 지원량은 독립 실험 개수가 아니다

같은 정확한 타겟 서열을 가진 train 레코드 수를 세어 지원량 좌표로 만들었습니다. 학습 데이터에서 그 타겟에 관련된 입력이 얼마나 있었는지 설명하는 단순한 값입니다. 분모와 레코드 정의를 명시합니다.

하나의 레코드가 하나의 독립적인 실험을 뜻하지는 않습니다. 같은 연구에서 나온 여러 분자나 반복 측정이 포함될 수 있습니다. 레코드 수를 독립 근거의 강도로 그대로 해석하면 정보량을 과장할 수 있습니다.

이 좌표는 데이터의 분포를 읽는 도움입니다. 실험적 증거의 질이나 모델의 오답률을 대신하지 않습니다. 결과를 층화할 때 다른 좌표와 함께 보고, 같은 타겟에 연결된 문제들의 의존성을 고려합니다.

S12 · 여섯 좌표를 한 숫자로 합치지 않는다

개인 초안은 화학적 거리, 최대 서열 동일률, 새로운 골격, pocket pLDDT, 실험 구조 상태와 타겟 train 레코드 수입니다. 연속값, 이진값, 범주와 미확인 상태가 섞여 있습니다. 각 좌표를 먼저 따로 봅니다.

화학적 거리는 클수록 낯설고, 서열 동일률과 지원량은 클수록 친숙할 수 있습니다. pLDDT는 구조 신뢰 정보이지 같은 난이도 척도가 아닙니다. 방향과 단위가 다른 값을 단순 평균하지 않습니다.

좌표를 통합하는 방법을 연구하려면 따로 학습하거나 평가 전에 규칙을 고정해야 합니다. 정답을 보고 가장 좋아 보이는 가중치를 test에서 찾으면 누출이 생깁니다. 이번에는 좌표 표와 개별 해석을 유지했습니다.

S13 · 12개 질문을 어떻게 골랐는가?

실제 cold-drug의 서로 다른 분자 12개에서 질문을 골랐습니다. 양성, 음성, 양성, 경계 레코드를 반복하는 학습용 할당으로 대상과 단위 처리를 연습하게 했습니다. 모델이 틀렸는지를 보고 고른 것은 아닙니다.

이렇게 의도적으로 섞은 작은 표본의 라벨 비율이 전체 DAVIS의 비율을 대표하지는 않습니다. 질문의 선택 과정과 제외 기준을 문서로 남겨야, 나중에 좋은 성능 숫자를 실제 분포의 결과로 오해하지 않습니다.

12개 질문에서 계산한 좌표는 4가지입니다. 구조 근거 두 열은 미확인 상태입니다. 빈칸을 임의의 최악 점수로 채우지 않았습니다. 질문 초안과 자동 점검을 사람의 교차 검증 완료로 표시하지 않습니다.

S14 · 작성자와 검증자는 다른 일을 한다

작성자는 질문과 대상, 정답 규칙과 출처를 정리합니다. 검증자는 같은 정보를 독립적으로 확인하며 모호한 부분을 찾습니다. 두 사람이 같은 작성 문장만 다시 읽는 것보다 원본을 따라가는 과정이 중요합니다.

분자 동일성, 서열과 변이, 측정 종류와 단위, 경계값 처리와 근거 범위를 확인합니다. 의견이 다르면 해결한 이유와 변경 이력을 남깁니다. 쿼리의 텍스트 수정이 정답 의미를 바꾸는지도 봅니다.

이번 자료에는 자동 계산과 초안 검토 항목을 준비했습니다. 독립적인 사람 둘의 검증을 수행했다고 표시하지 않습니다. 검토 상태를 미완료로 유지하며, 실제 참여자가 확인할 체크 항목과 관찰 노트를 남겼습니다.

S15 · 정답은 Agent가 쓰는 근거와 분리한다

평가 파일에 정답이 있어도 Agent에게 모두 보여주면 안 됩니다. Agent가 사용할 질문과 도구 근거, 채점기가 사용할 정답을 나눠 전달합니다. 정답을 검색 결과에 그대로 넣으면 연구 질문이 바뀝니다.

이번 하네스는 검증 코드의 동작을 배우기 위해 공급 레코드를 읽는 결정적 예제입니다. 그 사실을 명시하며, 숨겨진 정답을 추론하는 실제 LLM 벤치마크처럼 성능을 보고하지 않습니다.

실제 평가에서는 질문 구성과 도구 접근 범위, 어떤 DB의 측정값이 답으로 연결되는지 설계해야 합니다. 데이터의 공개 여부와 정답 누출 가능성을 함께 점검합니다. 좋은 실행 구조도 평가 문제의 정의를 대신하지 못합니다.

S16 · 작은 실습: 좌표 하나를 직접 대조한다

질문 하나의 분자 구조와 참조 train 목록을 읽고 가장 가까운 유사도를 확인합니다. 거리의 정의와 fingerprint 설정, 참조 split이 같은지 대조하세요. 값이 커졌을 때 무엇이 낯설다고 말할 수 있는지 적습니다.

서열 동일률 100%의 이유는 정확한 서열이 train에 있기 때문인지 확인합니다. 구조 열의 NA와 미조회 상태를 실제 생물학적 부재로 읽지 마세요. 아직 필요한 자료와 매핑 작업을 관찰 노트에 적습니다.

정답 규칙과 원본 측정값을 따라 한 질문을 다시 검토합니다. 자동 계산 성공을 교차 검증 완료로 표시하지 않습니다. 좌표 정의와 질문 의미의 일관성을 스스로 설명하는 것이 이 단계의 목적입니다.

S17 · 결과를 난이도로 나누려면 분모도 남긴다

좌표 구간별로 답변 비율과 오답률을 나눠 보면, 낯선 분자에서 자신 있게 틀리는지 확인할 수 있습니다. 구간별 전체 문제 수와 답변 수를 함께 남겨 작은 표본의 변화를 드러냅니다.

여러 좌표를 동시에 잘게 나누면 각 칸의 표본이 급격히 줄어듭니다. 보기 좋은 차이가 몇 문제의 변동인지 확인해야 합니다. 같은 분자나 타겟을 공유하는 질문의 의존성도 고려합니다.

구간 경계와 분석할 비교를 평가 전에 정하면 결과 해석이 더 명확합니다. 이번 12개 초안으로 일반적인 난이도 결론을 확정하지 않습니다. 다음 반복 평가 편에서 실제 로그를 좌표와 연결하는 흐름을 보겠습니다.

S18 · 핵심 요약: 낯섦과 근거를 정의한다

질문에는 대상과 정답 규칙, 원본 출처와 검토 상태가 필요합니다. 질문 식별자로 좌표와 실행 로그를 연결하세요. 명확한 데이터 구조가 있어야 모델이 어떤 문제에서 실패했는지 읽을 수 있습니다.

난이도 좌표는 train과의 친숙함과 근거 상태를 따로 기술합니다. 화학적 거리, 서열, 골격과 구조 정보를 같은 척도로 단정하지 않습니다. 미조회와 부재, 자동 점검과 사람 검증도 구분합니다.

이번 예제의 질문은 12개입니다. 계산 좌표는 4가지이고 구조 근거 두 열은 미확인 상태입니다. 이는 공식 스키마 동결이 아닙니다. 남은 자료와 검토가 무엇인지 명확히 쓰고 다음 교란과 반복 평가에 연결합니다.

S19 · 공식 자료와 개인 정의를 함께 표시한다

프로젝트의 큐레이션 방향은 Abstain-DTI 저장소와 온보딩 자료를 참고했습니다. 분자 표현의 동작은 RDKit 공식 문서와 실제 설치 버전으로 확인했고, 구조 신뢰 정보는 AlphaFold 공식 설명을 대조했습니다.

좌표 여섯 종류의 구체적인 정의와 이번 선택 방법은 개인 학습 초안입니다. query와 difficulty 파일, 프로토콜, 입력 해시와 실행 결과를 보관했습니다. 공식 프로젝트 평가 규약이나 검증된 전체 벤치마크로 표현하지 않습니다.

읽기 가이드에서 한 질문을 골라 대상과 수치를 원본까지 확인해 보세요. 관찰과 검토 상태는 사용자가 실제로 남길 기록으로 확인합니다. 다음 편에서는 도구 반환을 일부러 바꿔 같은 질문의 근거가 깨졌을 때를 시험하겠습니다.
