전체 표시 원고

S01 · 같은 질문을 세 번, 판단은 얼마나 바뀔까?

오늘 확실하다고 답한 후보를 내일은 보류한다면, 연구자는 어떤 판단을 따라야 할까요? 같은 질문을 반복했을 때 답변과 기권이 얼마나 바뀌는지 확인하는 것은 정확도와 별도의 질문입니다. 오늘은 그 변동을 로그로 읽습니다.

판단이 매번 같아도 모두 틀릴 수 있습니다. 반대로 일부 변동이 있다고 곧바로 나쁜 시스템이라고 단정할 수도 없습니다. 무엇이 바뀌었는지, 그 판단은 맞았는지와 어떤 입력에서 변했는지를 함께 봅니다.

앞선 감사 하네스의 실제 기록을 사용하고, 변동이 있는 작은 설명용 기록도 따로 만듭니다. 실제 러너는 결정적 규칙 기반이므로 LLM의 재현성을 측정한 결과로 표현하지 않습니다. 집계 원리와 분모를 먼저 공부합니다.

S02 · 같은 질문을 만들려면 조건도 고정한다

문장이 같아도 모델 버전, 프롬프트, 도구 목록이나 검색 결과가 바뀌면 같은 실험이 아닐 수 있습니다. 반복 평가에서는 무엇을 고정하고 무엇을 자연스럽게 변하게 둘지 먼저 정합니다. 버전과 실행 시각을 기록해야 해석할 수 있습니다.

도구 반환까지 고정하면 모델 내부 판단의 변동에 더 집중할 수 있습니다. 실시간 검색을 그대로 쓰면 외부 근거 변화도 함께 측정합니다. 둘 다 가능한 설계이지만 결과가 답하는 질문은 달라집니다.

이번 규칙 러너는 질문, 반환 주입과 코드가 반복마다 같습니다. 따라서 변동이 없는 것은 예상되는 동작입니다. 나중에 실제 에이전트를 연결하면 샘플링 설정과 캐시, 재시도 정책까지 함께 기록합니다.

S03 · 자유로운 문장을 비교 가능한 상태로 바꾼다

비교하려면 최종 행동을 정해진 형태로 저장해야 합니다. 답변인지 기권인지, 답했다면 어떤 라벨인지, 파싱 실패인지 실행 예외인지 나눕니다. 사람이 읽기 좋은 설명과 계산 가능한 상태를 함께 보관합니다.

기권과 시스템 오류를 같은 값으로 넣으면 변동 원인이 흐려집니다. 근거 부족으로 보류한 실행과 응답을 읽지 못한 실행은 다른 사건입니다. 실패한 실행을 조용히 빼면 남은 실행의 지표가 좋아 보일 수 있습니다.

질문 식별자, 조건과 반복 번호를 키로 사용합니다. 원시 출력에서 구조화된 결과를 만든 파서의 버전도 남깁니다. 이렇게 해야 나중에 파서를 수정했을 때 모델 판단이 바뀐 것처럼 잘못 읽지 않습니다.

S04 · 첫 질문은 답변과 기권 사이를 오간다

설명을 위해 만든 첫 질문은 세 번 중 답변, 기권, 답변을 냈습니다. 라벨은 답한 두 번 모두 양성입니다. 이 질문에서는 답변 여부가 바뀌었지만, 비교 가능한 두 라벨 사이에는 변화가 없습니다.

두 번째 질문은 세 번 모두 답했지만 라벨이 양성, 음성, 양성으로 바뀝니다. 답변 여부만 비교하면 안정적으로 보이지만 실제 결론은 변합니다. 기권 변동과 라벨 변동을 분리해야 하는 이유입니다.

세 번째 질문은 매번 같은 음성 오답을 냅니다. 이 예시는 변동이 없다는 사실과 정답이라는 사실이 다름을 보여주도록 만들었습니다. 설명용 기록을 실제 모델의 측정 결과에 섞지 않고 별도 파일에 둡니다.

S05 · 한 번이라도 바뀐 질문의 비율

첫 번째 정의는 한 질문의 반복들 중 답변 여부가 한 번이라도 다른지입니다. 답변과 기권이 모두 관찰되면 그 질문을 변동 있는 질문으로 셉니다. 질문 단위의 지표이므로 반복 횟수 자체를 분모로 쓰지 않습니다.

설명용 세 질문 중 답변과 기권을 오간 것은 첫 질문 하나입니다. 그래서 이 정의의 기권 변동률은 삼분의 일입니다. 모두 답한 두 번째 질문의 라벨 변화는 여기에 포함되지 않습니다.

반복 횟수를 늘리면 한 번이라도 다른 판단을 관찰할 가능성도 바뀝니다. 세 번의 결과와 열 번의 결과를 같은 조건처럼 비교하지 않습니다. 지표 정의와 반복 횟수를 함께 표시해야 합니다.

S06 · 반복 쌍 사이의 불일치를 세는 정의

다른 정의는 같은 질문의 반복들을 두 개씩 짝지어 답변 여부가 다른 비율을 셉니다. 세 번이면 비교 쌍은 첫째와 둘째, 첫째와 셋째, 둘째와 셋째의 세 쌍입니다. 질문 단위 지표와 분모가 다릅니다.

답변, 기권, 답변인 첫 질문에서는 두 쌍이 불일치합니다. 다른 두 질문은 답변 여부가 같으므로 불일치가 없습니다. 세 질문 전체의 아홉 쌍 중 두 쌍이 달라 쌍별 변동률은 아홉 분의 이입니다.

삼분의 일과 아홉 분의 이는 같은 기록에서 나온 다른 정의입니다. 둘 중 하나가 계산 오류라는 뜻이 아닙니다. 보고서에 단순히 flip rate라고만 쓰지 말고 무엇을 세었는지 수식과 원시 개수를 남깁니다.

S07 · 라벨 비교는 두 실행 모두 답했을 때

라벨 변동은 두 실행 모두 라벨을 내놓았을 때 비교합니다. 기권의 빈 라벨을 음성으로 처리하면 기권 변화가 라벨 변화에 섞입니다. 비교 가능한 쌍을 따로 세어 분모에 넣습니다.

설명용 첫 질문은 답한 두 번 사이 한 쌍만 비교할 수 있습니다. 두 번째와 세 번째 질문은 각각 세 쌍을 비교합니다. 전체 일곱 쌍 중 두 쌍의 라벨이 달라 라벨 쌍별 변동률은 칠분의 이입니다.

정의에 따라 질문별 다수결 일치율이나 다른 재현성 지표도 사용할 수 있습니다. 여러 지표가 같은 것을 측정하는 것처럼 섞지 않습니다. 특히 답변을 거의 하지 않는 시스템의 라벨 안정성은 답변 비율과 함께 해석해야 합니다.

S08 · 안정적인 오답도 가능하다

세 번째 설명용 질문의 실제 정답은 양성입니다. 하지만 세 번 모두 음성으로 답합니다. 기권 변동과 라벨 변동은 모두 없지만 정확도는 나쁩니다. 안정성만 높인 시스템이 믿을 만하다고 단정할 수 없습니다.

같은 잘못된 검색 결과를 캐시해서 반복 사용하면 같은 오류가 안정적으로 재현될 수 있습니다. 반복이 독립적인 근거를 제공했는지 확인해야 합니다. 세 번의 일치가 세 개의 독립 실험과 같지 않습니다.

정확도, 답변 비율, 선택적 오답률과 변동을 나란히 보세요. 연구에서는 언제 오류가 고정되는지와 언제 판단이 흔들리는지 둘 다 중요합니다. 정답과 원시 근거가 없는 반복 표만으로 품질을 평가하지 않습니다.

S09 · 실제 하네스의 기록을 묶는다

앞선 실제 개인 실습은 질문 12개, 조건 4개, 반복 3회로 실행 기록 144개를 남겼습니다. 이를 질문과 조건으로 묶으면 48개의 반복 그룹이 됩니다. 각 그룹에는 같은 조건의 세 실행이 들어 있습니다.

조건을 섞어서 묶으면 원본과 교란의 차이를 반복 변동으로 잘못 셀 수 있습니다. 반복 그룹의 키를 먼저 확인하고, 각 그룹에 기대한 반복 번호가 모두 있는지 검사합니다. 누락과 중복도 따로 기록합니다.

실습 코드는 원시 실행 파일을 다시 읽어 행동과 라벨의 쌍을 계산합니다. 요약 표를 수작업으로 복사하지 않습니다. 입력 파일 해시를 남겨 어떤 로그에서 이 숫자가 계산되었는지 추적할 수 있습니다.

S10 · 실제 규칙 러너의 변동은 없었다

실제 규칙 러너의 48그룹에서는 기권 변동과 라벨 변동이 모두 0이었습니다. 같은 입력과 같은 코드로 실행한 결정적 검사기이므로 예상되는 결과입니다. 반복 집계가 제대로 연결되는지 확인하는 기준선입니다.

이것을 LLM 에이전트가 항상 일관된 판단을 한다는 결론으로 바꾸지 않습니다. 이번에는 LLM을 호출하지 않았습니다. 모델의 샘플링, 계획과 도구 선택의 변동은 실제 백엔드를 연결한 뒤 측정해야 합니다.

앞서 검사 없는 교란 조건에서는 같은 오답도 반복되었습니다. 따라서 이 실제 기록에서도 변동이 없다는 사실은 정확함을 보장하지 않습니다. 반복 표와 조건별 오류 표를 함께 읽으면 두 질문의 차이가 분명해집니다.

S11 · 144기록은 144개의 새 질문이 아니다

같은 질문을 여러 조건과 반복에서 사용하면 실행 수는 늘어나지만 새 질문이 늘어나는 것은 아닙니다. 이번 데이터의 고유 질문은 12개입니다. 표본 수를 보고할 때 고유 질문과 실행 기록 수를 나란히 둡니다.

같은 분자나 타겟을 여러 질문이 공유하면 질문끼리도 관련이 있을 수 있습니다. 모든 기록을 독립 행처럼 다루어 불확실성을 계산하면 지나치게 좁은 범위를 얻을 수 있습니다. 평가의 단위와 공유 개체를 검토해야 합니다.

반복은 한 문제에 대한 행동의 변동을 보고, 더 많은 고유 질문은 평가 범위를 넓힙니다. 서로 다른 목적을 가진 자원입니다. 다음 실험 예산을 정할 때 같은 문제를 더 반복할지 새로운 문제를 더 검증할지 선택할 수 있습니다.

S12 · 만들 수 없는 지표는 비워 둔다

ECE에는 예측의 신뢰도와 실제 정답이 필요합니다. AURC에는 답변 우선순위를 만들 의미 있는 점수가 필요합니다. 이번 규칙 러너는 이런 신뢰 점수를 출력하지 않으므로 LLM 지표를 만들어 채우지 않습니다.

API 비용이나 토큰 사용량도 실제 모델 호출이 있어야 측정할 수 있습니다. 이번 실행의 모델 호출 비용은 없지만, 이것이 실제 에이전트 운영 비용이 0이라는 뜻은 아닙니다. 로컬 실행 시간과 모델 비용은 다른 항목입니다.

없는 값은 없다고 표시하고 필요한 입력을 문서화합니다. 지표가 많아 보이도록 임의의 confidence를 붙이면 해석이 흐려집니다. 실제 백엔드를 연결할 때 로그 스키마에 점수, 토큰과 지연 시간을 추가하고 검증합니다.

S13 · 난이도로 나눌 때 표본 수도 읽는다

난이도 좌표를 실행 로그와 질문 식별자로 연결하면 가까운 분자와 낯선 분자의 오류를 나눠 볼 수 있습니다. 이때 전체 질문 수와 각 층의 고유 질문 수를 먼저 확인합니다. 반복 기록 수만 크게 보이면 표본의 폭을 오해하기 쉽습니다.

이번 작은 쿼리에서는 정한 화학 거리 기준으로 가까운 층에 한 질문, 먼 층에 열한 질문이 들어갔습니다. 이를 세 번 반복한 개수와 고유 질문 개수를 구분해서 표에 남겼습니다. 층 사이 성능을 일반화할 만큼 넓은 표본은 아닙니다.

구조 신뢰도 좌표는 아직 조회하지 않았으므로 그 값으로 층화한 결과를 만들지 않습니다. 결측과 미조회 상태를 함께 표시합니다. 난이도 표는 자동으로 인과관계를 설명하는 값이 아니라 실패 위치를 찾는 진단 도구입니다.

S14 · 실패 모드를 원시 로그로 분류한다

검색 실패, 잘못된 대상 선택, 단위 오류와 추론 오류는 다른 문제입니다. 최종 라벨이 틀렸다는 사실만으로 어느 단계가 원인인지 정할 수 없습니다. 도구 요청과 반환, 계산과 최종 설명을 함께 읽어야 합니다.

이번 감사 기록은 규칙 검사의 불일치 이유를 실제 필드와 연결했습니다. 한 실행이 여러 이유를 가질 수 있어 이유 수를 합친 값은 실패 실행 수와 다를 수 있습니다. 분류표의 단위도 명시합니다.

LLM 로그를 검토할 때는 작성자와 검증자가 같은 근거로 분류하는지 확인할 수 있습니다. 원인 추정과 로그로 직접 확인한 사실을 구분하고 애매한 사례를 보류합니다. 모델의 설명 문장만으로 내부 원인을 확정하지 않습니다.

S15 · 불확실성 범위도 평가 단위에 맞춘다

점 추정값만 보고 작은 차이를 우열로 해석하지 않습니다. 더 많은 독립 질문과 적절한 평가 설계가 있어야 변동의 크기를 볼 수 있습니다. 이번 소규모 규칙 예제에는 일반적인 LLM 성능의 신뢰 구간을 붙이지 않았습니다.

추가 분석에서 재표집을 사용한다면 반복 실행을 따로따로 뽑는 것보다 질문의 반복 묶음을 보존하는 방식을 검토합니다. 공유 타겟이나 약물이 중요하면 그 묶음도 고려할 수 있습니다. 어떤 무작위성을 추정할지 먼저 정합니다.

질문별, 조건별 지표와 원시 개수를 저장하면 다른 사람이 가정을 바꿔 다시 계산할 수 있습니다. 작은 차이를 크게 보이게 하는 그래프보다 표본과 계산 정의가 분명한 결과가 유용합니다. 이번 도식은 곡선 개념 예시입니다.

S16 · 수치 동결 전에 확인할 목록

결과를 확정하기 전에는 쿼리와 정답, 분할과 난이도 정의, 모델과 프롬프트, 파서와 평가 코드 버전을 맞춥니다. 입력과 실행 파일 해시를 남기면 같은 결과를 다시 만들기 쉬워집니다. 무엇을 동결했는지가 핵심입니다.

실패한 사례를 보고 프롬프트를 고친 뒤 같은 test에서 좋아진 숫자는 후속 탐색 결과입니다. 기존 동결 결과를 덮어쓰지 않고 변경 이력과 새 실행을 분리합니다. 최종 검증이 필요하면 독립 평가 자료를 준비합니다.

현재 개인 실습의 프로토콜과 로그는 공개 학습 자료로 정리하지만 공식 프로젝트의 수치 동결로 표현하지 않습니다. 인간 교차 검증과 실제 에이전트 실행은 아직 다음 단계입니다. 확인한 범위를 기록하는 것이 재현의 출발점입니다.

S17 · 작은 실습: 반복표를 손으로 계산한다

설명용 세 질문의 아홉 실행을 가이드에서 읽습니다. 먼저 질문별로 답변과 기권이 모두 있었는지 표시하세요. 다음에는 각 질문에서 반복 쌍 세 개를 만들어 불일치를 세어 보세요. 두 분모의 차이가 직접 보입니다.

라벨 비교에서는 두 실행 모두 답한 쌍만 남깁니다. 기권을 음성으로 바꾸지 말고 빈 라벨로 유지하세요. 세 번째 질문의 정답과 출력을 대조하면 안정적인 오답을 확인할 수 있습니다.

그다음 실제 144기록을 조건별로 묶은 결과와 비교합니다. 관찰 노트에는 지표의 정의, 분모와 변동이 없을 때의 한계를 적습니다. 실행 성공을 학습 완료로 표시하지 않고, 자신의 설명과 남은 질문을 남겨 보세요.

S18 · 핵심 요약: 같은 답도 따로 검증한다

반복 평가에서는 질문과 조건을 고정하고 답변, 기권과 오류를 구조화합니다. 기권 변동과 라벨 변동은 다른 사건입니다. 질문 단위와 반복 쌍 단위의 분모를 수식과 함께 표시하세요.

안정성은 정확함을 보장하지 않습니다. 같은 잘못된 근거를 반복 사용하면 같은 오답도 재현됩니다. 정답, 답변 비율과 선택적 오답률, 난이도와 실패 모드를 함께 읽어야 합니다.

실제 규칙 예제는 집계의 기준선을 확인한 단계입니다. LLM을 연결할 때는 버전, 독립 실행과 인간 검증 쿼리, 실제 비용과 점수가 더 필요합니다. 핵심 학습 흐름을 마친 뒤 자신의 관찰을 남기며 다음 실험을 설계할 수 있습니다.

S19 · 출처와 다음 실제 벤치마크 단계

전체 평가 관점은 Abstain-DTI의 소개와 온보딩 계획을 참고했습니다. 이 영상의 변동 정의와 작은 예시는 개인 학습용으로 명시한 프로토콜입니다. 공식 평가 규약이나 리더의 프로젝트 결과로 표현하지 않습니다.

실제 감사 로그를 읽은 집계 결과와 별도로 만든 설명용 기록을 분리해 저장했습니다. 계산 코드와 입력 해시, 조건별 표와 관찰 가이드를 함께 확인할 수 있습니다. 영상의 도식도 이 데이터와 정의에서 직접 만들었습니다.

다음에는 검증된 질문을 더 모으고 실제 모델 백엔드와 도구 실행을 연결할 수 있습니다. 그때 재현성과 정확도, 기권과 비용을 같은 정의로 측정합니다. 지금은 핵심 요약을 돌아보고 자신의 관찰 노트를 채우며 공부를 이어가세요.
